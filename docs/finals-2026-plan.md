## 1. 决策与目标

继续基于 AI Airlock 现有实现升级，以“让 Agent 在敏感材料上，通过受控补充证据，完成可信业务任务”
作为决赛主线。重点交付三项能力：

1. **可信边界**：明确并验证 Airlock 接口、原始资料与宿主工具之间的实际权限关系。
2. **受控补证**：首轮提供预算内的净化证据，缺少关键线索时在固定授权范围内补充新证据。
3. **可核查成果**：Agent 完成有证据引用的事故复盘及客户沟通稿。

冲刺一等奖是优化目标，不是名次预测。当前没有足以判断全部对手水平或获奖概率的信息。
现有方案的主要竞争风险是：被概括为“规则脱敏加向量检索”，而缺少实际任务收益和不可绕过边界的证据。

本轮不扩展为通用办公平台，不同时重写 PDF/OCR/Office 解析、全部检测器和全部硬件后端。
可复用现有文本、CSV、日志和合成事故资料；仍须先核对实际允许的输入类型。

## 4. 决赛场景与交付

目标用户：需要借助生产力 Agent 分析客户故障、但材料含敏感信息的软件技术支持或运维人员。

主任务：从事故日志、配置、客户样例和变更记录中，识别故障时间线、根因、影响范围和修复建议，
输出带证据引用的内部复盘以及去除敏感信息的客户沟通稿。

保留支付事故底座，同时新增未用于调参的其他事故案例。材料若为合成，必须明确标注；
可邀请真实开发者试用并记录反馈，不虚构客户、业务损失或商业验证。

建议的真实 Skill 协作：事故处理 Skill 调用 Airlock，获得安全证据后再调用报告 Skill。
记录实际调用轨迹；不能把普通函数调用算作多个 Skill，或把外层编排能力算作 Airlock 自身能力。
若宣传 Airlock 既调用其他 Skill 又被其他 Skill 调用，两个方向都要有独立轨迹。
下游报告 Skill 只能收到净化证据，不能重新取得原始文件。

## 5. 受控补证设计与验收

### 建议协议（未实现，不是可用 API）

1. 用户授权明确的资料范围，本地端建立完整授权语料的净化快照。
2. 为案例分配稳定 ID、版本、证据 ID 与相对来源定位；快照不暴露原始值或敏感绝对路径。
3. 首轮在预算内生成 Capsule；Agent 给出具体证据缺口，不凭模型自报置信度扩大权限。
4. 概念接口 `fetch_evidence(case_id, question, seen_ids, budget)` 检索完整净化快照，
   返回新的证据增量。最终接口名和 schema 在实现时确定。
5. 首轮之后最多再补充两轮。服务端执行总预算、单次数量、调用次数和案例范围限制，
   不信任调用方自行传入的限制值。
6. 无新增证据、预算耗尽、证据冲突或资料不足时停止并解释不确定性。

固定快照上的新问题检索可以提供真正的新信息；仅在首轮 Capsule 内重新排序不能算补证。
重新读取发生变化的原文必须建立新版本并重新检查，不在同一会话静默替换输入。
同一案例内保持匿名标识一致，以支持跨日志关联；不同案例不默认共享身份映射。

验收清单：

- [ ] 至少一个开发案例展示“首轮不足 → 指明缺口 → 新证据 → 正确结论”，且不能靠直接硬编码答案完成。
- [ ] 独立测试案例也能提供新增有效证据；结果和失败均记录。
- [ ] 每条引用属于当前案例和版本，能够定位真实证据。
- [ ] 不能用新查询跨目录、跨案例、增加授权范围或超过服务端预算。
- [ ] 首轮、补证、错误响应、日志与来源元数据均经过相应敏感信息检查。
- [ ] 循环次数、返回数量和累计预算有程序级上限；重复请求与超时行为明确。
- [ ] `BLOCK`、非法响应或错误不能触发 raw read、上传原文或未声明的模型回退。
- [ ] 最终报告说明证据不足或冲突，不能靠编造填补。

## 6. 权限边界与安全声明

优先验证：Airlock 有权读原始目录，而宿主实际运行身份无权读原始目录，只能调用受限接口。
使用真实文件权限、独立身份或隔离环境；移动文件夹、忽略文件和提示词不构成强隔离。

必须在测试身份下尝试宿主实际开放的文件工具、终端等读取入口，并记录拒绝结果。
同时核对编辑器预读、索引、附件、历史会话等可能已暴露原文的路径。
Airlock 服务端也要校验调用者和案例访问范围；会话 ID 不能自行视为充分授权。
不得用生产凭据测试；使用合成标记，且不得把合成测试结果外推为全面安全证明。

- 强制隔离实测通过：可以按已验证环境、身份和入口描述原文访问限制。
- 强制隔离不可用：明确为经 Airlock 接口提供净化证据的协作式接入，
  不宣称宿主无法访问原文或具备系统级防泄露能力。
- 检测器只覆盖已识别格式和模式；embedding 不承担注入检测效果的归因。
- 任何本地生成模型都不能独自决定敏感数据放行；其输出仍需验证。
- 安全泄漏或错误放行属于发布阻断，不得为了按时录制降低原有门槛。

## 7. 评测与发布验收

### 对照实验

固定授权材料、任务、宿主模型、生成设置、评分规则和预先声明的资源限制，对比：

| 方案 | 检验的问题 |
|---|---|
| 原始上下文 | 完整材料下的任务效果与敏感信息暴露 |
| 普通脱敏 | 只做安全变换是否已足够 |
| Airlock 单轮 | 任务筛选的收益、代价与遗漏 |
| Airlock 补证 | 新证据对正确性与累计开销的影响 |

原始上下文对照只使用合成或明确获准公开的材料，不能为实验上传真实敏感数据。
先冻结未参与调参的测试集及输入版本；开发集与测试集分开。
建议安排 15–20 个独立任务，覆盖正常、跨文件关联、缺证、恶意混入、误拦截及无法回答。
这是小规模工程验收目标，不是泛化能力保证；实际数量和原因必须如实记录。
如果看过测试结果后继续调参，该数据不再作为未见测试集，需另留新案例。

### 记录指标

- 最终任务正确性：根因、因果链、建议及引用是否符合预先规定的评分标准。
- 关键证据保留、无依据断言、误拦截与正常任务成功情况。
- 已知合成敏感标记在可观察模型请求、工具输出、报告、错误及审计表面的命中情况；
  同时报告检查表面与观察盲区。
- 所有轮次累计输入输出 token；优先使用模型 usage 或对应 tokenizer，
  不能获取时明确标注估算器。不同方案不能混用估算与精确值作无说明比较。
- 用户端总耗时、各阶段耗时、失败数；区分首次准备、进程启动、预热与模型常驻。
- 小样本报告逐次记录，不只选最快或最好的一次；不把末轮 Capsule 大小当累计成本。

### 功能准入

- 两轮补证在预先指定的缺证任务上带来实际正确性收益，且不能出现新增安全放行缺陷。
- 普通任务不出现未解释的质量或稳定性回退；若有任务收益与代价取舍，逐项公开。
- 若补证收益不稳定或破坏演示可靠性，提交稳定单轮版本，删除补证已验证的宣传。
- 关键现场流程连续演练 10 次并报告真实成功数；目标为 10/10。
  这不替代独立任务评测，也不构成全面可靠性证明。
- 最终运行包须重新验证相关回归、真实模型路径、指定宿主与目标硬件；
  CI 中因缺模型而 skip 的测试不能算模型实测通过。
- 所有新增数值经 [Claims Ledger](claims-ledger.md) 记录来源、版本、设备、样本和限制，
  再进入 README、文章、图片和视频。

## 8. OpenVINO、模型与性能取舍

先在已落实的 Core Ultra 上完成 CPU 本地推理和宿主任务，再按实测优化：

1. 分开测量进程启动、模型加载或编译、tokenization、embedding、ranking、策略检查与序列化。
2. 对最大开销评估模型复用、编译缓存、净化后证据 embedding 缓存。
   引入常驻服务时，补齐调用鉴权、案例隔离、缓存版本、过期清理和故障回收。
3. CPU 与一个可用加速设备在同机同模型同任务比较，同时检查质量、启动成本和依赖。
4. GPU/NPU、量化探索先限时半天；兼容性或收益不明确时停止，避免阻塞主要交付。
5. 不承诺换 NPU 就更快；不同时扩展全部设备、模型和动态调度。

本地生成式模型为条件项：若组委会确认是硬要求，则升为 P0，并选择一个窄任务，
如基于净化证据生成结构化摘要或补证问题。否则只有可测收益才加入。
模型下载、驱动、内存、时延、输出验证和再分发许可都必须计入成本。

弱网或离线演示只声明已实现的本地能力。模型已准备时可验证本地净化、检索和证据包输出；
云端诊断不可用时明确暂停，不能声称完整云端任务离线成功。
现有 fail-closed 合同不得因所谓降级而静默改成 lexical、云端原文处理或其他未验证后端。

## 10. 演示、提交与答辩

演示重点是三个真实片段：

1. 普通脱敏或单轮容易遗漏线索的任务，新版补证带来新证据与可核查结论。
2. 诱导越权读取或泄露的尝试，展示实际权限/接口拒绝结果及其适用范围。
3. 最终报告展开一项结论，追踪到来源证据与处理过程。

若某项功能未验收，替换为已验证流程，不使用模拟 UI 伪装真实宿主。
保留未剪辑原始录像；公开剪辑可以更简洁，但不能隐去失败、预置答案或人工介入造成误导。
正式视频时长与格式以主办方回复为准。

提交前：

- [ ] 确认作品身份、最终包源码版本、依赖、模型 revision、平台及许可记录。

- [ ] 文章、视频、PPT、README 数字来自同一已注明的证据，版本差异明确。
- [ ] Core Ultra、宿主、本地推理及限制与实测一致。
- [ ] 公开链接匿名可访问；图片、视频与下载有效。
- [ ] 完成决赛表单并保存真实成功回执；不把草稿、预填或上传过程当作提交成功。
- [ ] 个人联系方式、地址、登录凭据、真实客户原文不进入公共仓库。
