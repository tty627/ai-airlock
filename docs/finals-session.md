# 决赛实验：固定资料范围内的受控补证

此文说明决赛开发分支的 session 接口。它与已发布 rc.7 的 `scripts/run.ps1` 单轮接口分开；
不是新的发布验收结论，也不把旧版本 PASS 转移到新实现。Core Ultra、指定生产力宿主、
Windows 不同身份权限隔离和真实最终任务质量仍需按 [宿主验收](finals-host-acceptance.md) 实测。

## 工作方式与边界

资料所有者在 Agent 任务开始前，用独立身份启动本地 Airlock 服务。服务读取指定材料一次，
建立固定的净化案例，并在 `127.0.0.1` 随机端口提供访问接口。首轮提供预算内证据；
Agent 指明缺失信息后，最多再补证两轮，检索范围始终是该案例的完整净化快照。

连接文件保存本地 endpoint、bearer 凭据及案例身份，不含原始目录参数。
知道案例 ID 不足以访问接口；客户端还需要连接凭据。此凭据授予的是该会话净化结果的访问能力，
应按凭据管理，不上传、不打印、不放进模型消息或仓库。文件只交给预定宿主的客户端读取。

**真正的原文隔离依赖运行身份和文件权限。** 同一账户下把文件放到另一个目录，不会剥夺 Agent
的访问权；localhost 与 bearer 也不能阻止具备原始目录权限的进程直接读文件。
本实现提供受控接口，只有验收记录才能证明具体宿主身份被拒绝访问哪些原文入口。

| 内容 | 资料所有者 / Airlock 服务端 | 生产力 Agent / 客户端 |
|---|---|---|
| 原始资料目录 | 明确授权并可读 | 测试目标是不可读；须实测 |
| 模型与程序 | 预先安装，模型准备不属于 Agent 任务 | 使用已安装客户端 |
| 连接文件 | 在工作区外新建并控制权限 | 客户端可读；不将内容交给模型 |
| 已披露证据与报告 | 受案例、预算和输出检查约束 | 可用于当前任务；不能扩大原文权限 |

净化快照和来源证据发布会检查原文中已经识别的敏感值。Agent 发来的问题与稿件使用独立的
敏感模式检查，不与隐藏原文的敏感值集合比较，也不把新问题里的值加入固定保护集合。
否则 Agent 可以反复提交猜测，再从成功或失败判断“这个值是否出现在原文中”，把检查接口变成秘密猜测渠道。
这项设计限制不是对所有推断攻击的完整证明；宿主也不得主动猜测或还原已变换的敏感值。

## 1. 所有者准备模型和服务

以下是所有者终端中的命令，**不是让生产力 Agent 执行的操作**。使用 Python 3.12 和本分支完整安装；
模型准备方式沿用仓库固定 revision。准备阶段可能联网，服务的检索与过滤本身在本机执行。

```powershell
python -m pip install -e '.[openvino]'
python scripts/prepare_embedding_model.py
python -m airlock.session_server `
  --path 'C:\AirlockPrivate\payment-case' `
  --task '分析支付故障，给出有证据引用的内部复盘与客户沟通稿' `
  --connection 'C:\AirlockSessions\payment-session.json' `
  --relevance-backend openvino
```

替换为实际绝对路径，并在运行前建立相应目录和身份权限。连接文件应是新文件；不要覆盖仍使用中的会话。
服务进程需要持续运行。所有者可在停止服务后清理连接文件；重新载入变更过的材料时，应新建服务、
新连接文件并重新开始任务，不能沿用旧案例的证据引用。

服务默认存活 3,600 秒，允许用 `--lifetime-seconds` 设为 1–3,600 秒。正常关闭时尝试删除自己创建且
内容未改变的连接文件；异常终止后所有者检查并清理残留。连接不会自动续期，重启会产生新的案例身份。
服务最多处理 100 次经过鉴权的请求；请求上限不会因重试 ID 而取消。

如使用已验证的其他本地模型目录，服务支持显式 `--model-dir '<model directory>'`。
OpenVINO 是 session 默认后端；模型不可用时应修复准备步骤，不能悄悄切换为 lexical。
`--relevance-backend lexical` 只供明确选择的开发诊断和无模型协议测试，不能作为本地模型推理或决赛硬件证据。

原文权限由所有者按现场 OS 和账户配置，不能通过一个通用复制命令假定完成。
Windows 上应记录实际服务账户、宿主账户、目录 ACL 和模型目录权限，再从宿主身份验证访问拒绝。
若运行方式无法隔离身份，可继续测试接口，但标为“协作式接入，原文强隔离未验证”。

## 2. 宿主开始任务与补证

宿主只拿到连接文件的路径和任务说明，不需要知道原始材料路径。
不要在宿主里用文件预览、`Get-Content`、附件或编辑器打开连接文件；直接将路径交给客户端。
连接路径、问题、request ID、草稿路径都作为独立字面量参数传递。拼接 PowerShell 命令时，
每个值使用单引号包裹，值里的单引号写成两个单引号 `''`；不得把问题文本当作可执行代码插入。

```powershell
python -m airlock.session_client `
  --connection 'C:\AirlockSessions\payment-session.json' begin --json

python -m airlock.session_client `
  --connection 'C:\AirlockSessions\payment-session.json' `
  query --question '故障开始前是否有部署或配置变更？需要时间与变更内容。' `
  --request-id 'payment-change-01' --json
```

每次新问题使用新的 request ID；网络重试同一问题时复用原 ID，避免重复占用披露预算和推进轮次。
这是请求幂等规则，不授权客户端非零失败后的自动重试；错误后先停止，由所有者诊断并决定如何恢复。
query 不接受新目录或跨案例选择；不能通过问题文本要求解码匿名标识、读取凭据或绕过服务端限制。
问题中的已识别敏感模式先被净化，再用于检索；其处理不查询隐藏原文秘密是否与问题相同。
先检查客户端退出状态和返回数据，再使用其中的证据，不把错误响应当作分析材料。

停止条件包括：无新增证据、预算或两轮补证上限到达、策略阻断、会话关闭、非法响应或请求失败。
正常耗尽时保留已获得的证据并说明缺口；出错时停止继续调用，报告错误，不自行绕过或更换模型。
证据互相矛盾时，在结果中说明矛盾，不能任选一条装成已确认结论。

当前协议为 `schema_version=finals-session-v1`。`begin/query` 成功时，`status=OK`，
证据位于 `safe_context.facts`，每条含 `id`、`text`、`source`、`local_ref`、`start_line`、`end_line`。
`NO_NEW_EVIDENCE` 表示没有可新增证据，不代表已经回答了问题。引用的行号属于**净化快照**；
多行替换可能改变原始文件行号，不能把它们宣传为原文逐行定位。

默认最多两轮补证、每轮三条证据、问题 2,000 字符，累计披露预算为估算 6,000 tokens。
这些限制由服务端执行，当前 owner CLI 不开放放宽参数。`budget` 里的计数包含每次新增证据响应的
完整 canonical JSON 和元数据，排除缓存重试与报告；估算器是 `utf8_bytes_div_4_ceil_v1`。
完整 Agent 的输入、思考、输出、重试和报告开销需要另行采集。`begin` 重试返回首轮原始计数，
应以最新一轮响应记录累计披露量。

检索每轮最多考虑 64 个候选，再按完整响应 JSON 的预算选择实际释放的证据，默认仍只释放最多三条。
因此，前排大候选放不进预算时，仍有机会选择后面较小的候选；64 个候选上限不代表全语料必然穷尽，
也不构成相关证据全部召回的保证。

客户端成功将 JSON 写入 stdout，失败返回非零状态并在 stderr 给出固定 `SESSION_CLIENT_FAILED`，
不释放服务端细节。不能仅凭这个通用错误区分超时、凭据问题、预算或稿件拒绝；需要所有者在安全范围内诊断。

## 3. 形成可核查报告

Agent 可以分别编写内部复盘和客户沟通段落。所有事实性主张都应引用当前会话已经披露的证据 ID；
建议与推断应在文字中标明，不把它们写成已观察事实。不要把被替换的值还原到客户稿。

下面仅为 JSON 形状示例。`<实际返回的证据 ID>` 必须替换为服务真实返回值，示例不是可直接验收的稿件。

```json
{
  "title": "支付服务事故复盘与客户沟通稿",
  "sections": [
    {
      "heading": "观察与初步判断",
      "claims": [
        {
          "text": "此处填写与已披露证据一致的观察；推断须明确标注。",
          "evidence_ids": ["<实际返回的证据 ID>"]
        }
      ]
    }
  ],
  "unresolved_questions": ["此处列出当前材料仍无法回答的问题。"]
}
```

将只含净化信息的草稿保存在独立输出目录，再执行：

```powershell
python -m airlock.session_client `
  --connection 'C:\AirlockSessions\payment-session.json' `
  report --draft 'C:\AirlockOutputs\payment-draft.json' --json
```

report 检查稿件格式、引用是否属于本案例已披露的证据，以及独立可识别的敏感模式。
它**不将 Agent 稿件与隐藏原文敏感值比较**：如果稿件通过与否取决于猜测是否命中原文，
即使错误消息不显示原文，也会暴露匹配结果。
**它不检验引用是否支持这句话、不自动评分根因正确性，也不能保证识别 Agent 自行猜入的无格式秘密。**
通过引用校验不等于事实审核通过。诊断质量应通过预先冻结的答案标准、独立审阅与真实宿主结果评测。
如所有者需要结合原文敏感值审核最终稿，应在所有者本地进行；不能将逐项秘密匹配、命中与否或由该匹配
直接决定的通过/失败结果反馈给 Agent。当前 report 接口不提供这种原文知情审核。

可选的 `airlock-incident-report` Skill 位于源码仓库的 `integrations/airlock-incident-report/SKILL.md`，
提供独立报告步骤，源码目录单独安装；主 Skill release archive 仍只包含一个 `SKILL.md`。
两个 Skill 都被真实宿主发现并产生实际调用轨迹后，才能声称完成了多 Skill 协作。

## 测量与复现

补证的代价必须累计全部轮次。报告至少包括每轮新增证据、引用有效性、累计披露量、最终任务质量、
端到端时间、模型与设备。仅客户端证据 JSON 大小不能代表完整 Agent token 用量；
如果没有模型 usage，就注明估算范围和估算器，不把工具输出估算冒充全流程成本。

独立开发演示见 [demo/finals/README.md](../demo/finals/README.md)。它不属于独立未见评测集，
脚本执行与预设补证问题不等于真实 Agent 自动决策或多 Skill 协作。

对照入口为 `benchmark/run_finals_eval.py` 与 `benchmark/finals_cases.json`。
先看该脚本的 `--help` 和 [benchmark 说明](../benchmark/README.md)，
区分原文、普通脱敏、单轮和补证对照。协议测试与证据覆盖率不等于真实模型最终答案正确率。

连接凭据、服务输出、运行日志、报告与截图不要提交到公共仓库或放入 Skill 包。
公开证据另做合成标记和敏感内容检查；不能为了复现让真实客户原文越过既定边界。

## 当前验收阻塞

- Core Ultra 设备、OS/驱动与模型实际推理尚需回填。
- QwenWork、WorkBuddy、TRAEWork 或豆包办公等宿主需要逐个确认实际接口和安装方式；
  TraeCode/Qoder 旧文档不证明这些产品已经兼容。
- 不同运行身份的 Windows 原文读取拒绝、宿主索引与附件旁路需要连续证据。
- 独立任务效果、真实 Skill 协作、10 次现场主流程与材料发布仍需执行。
- embedding 是否满足组委会“本地大模型”的措辞要求，仍需主办方答复。
